# Skillfy Blueprint & Autonomous Skill Architect

This skill defines the architectural specification and scaffolding template used by `/skillfy` when extracting reusable knowledge from user interactions and document styles.

---

## 1. Principles of Skill Authoring

When `/skillfy` generates a new skill in `custom_skills/` or `skills/`:

1. **Zero Hardcoded Client Secrets or Sensitive Data**:
   - Never hardcode client company names, internal server hostnames, employee names, or project codes in global skills.
   - Separate **Universal Methodology** (the structure, rules, formatting conventions) from **Instance Data** (specific numbers or findings).
   - Local user skills (`learned-*.md`) created on a user's machine stay in `custom_skills/` or `skills/` and are ignored by git (`.gitignore`).

2. **English Instructions for Maximum AI Reasoning Fidelity**:
   - Write all operational rules, step-by-step procedures, decision trees, and validation constraints in clear, unambiguous **English**.
   - Specify that **output content** must be generated in the **active document's native language** (Spanish, Portuguese, English, etc.).

3. **Step-by-Step Expected Mockup / Pipeline**:
   - Every learned skill must provide a concrete "Mockup of Expected Output" (Maqueta de lo esperado) showing the ideal markdown structure, table layout, or exhibit format.

---

## 2. Standardized Skill Scaffolding Template

All skills generated by `/skillfy` MUST follow this exact YAML frontmatter and markdown structure:

```markdown
---
name: [Short Descriptive Title]
description: [1-2 sentences summarizing capability and triggers]
hosts: [Word, Excel, PowerPoint] # or specific host
alwaysActive: false
keywords: [keyword1, keyword2, keyword3, ...]
---

# [Skill Title]

## 1. Overview & Objective
Briefly describe the business scenario, target documents, and expected outcome.

## 2. When to Apply This Skill
- Condition A: ...
- Condition B: ...

## 3. Step-by-Step Procedure & Decision Logic
1. Step 1: Analyze document context and extract input parameters.
2. Step 2: Apply structural rules and brand formatting.
3. Step 3: Validate metrics and cross-references.

## 4. Expected Output Mockup (Maqueta del Resultado)
Illustrate the exact visual/textual structure expected:
```
[Cover / Header Block]
[Summary Table Layout]
[Visual Exhibit Triad: Caption -> Chart -> Analysis]
[Technical Evidence Structure]
```

## 5. Negative Constraints (What NOT to do)
- Do NOT hardcode static values.
- Do NOT mix typography.
- Do NOT delete caption or narrative anchors.
```

---

## 3. Skillfy Quality Checklist

Before saving a learned skill, verify:
- [x] Does the YAML frontmatter parse cleanly?
- [x] Are the instructions written in precise English?
- [x] Is the output language specified to match the document's language?
- [x] Does it include a structural mockup / blueprint?
- [x] Is client-confidential data completely excluded?
